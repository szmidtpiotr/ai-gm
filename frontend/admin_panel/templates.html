Bulk Import Templates

← Admin Panel

Reference for JSON arrays used with admin bulk import. In the admin panel, open the matching Game Design sub-tab (Skills, Weapons, Loot Tables, …) and expand Bulk import (JSON array) — paste the array there (Dry run / Commit). This page is a copy-friendly reference; no login required here.

Source of truth dla kontekstu GM (kolejność priorytetu): najpierw game_config_items — jeden skonsolidowany katalog przedmiotów (typy m.in. armor, consumable, misc, quest, narrative; efekty zużywalnych przez effect_type / effect_dice), potem broń (game_config_weapons), wrogowie, NPC, lokalizacje, loot tables itd. Pełny eksport do LLM: GET /api/admin/config/catalog-snapshot (Admin Panel → eksport snapshotu). Szablony poniżej trzymają się tej hierarchii: wpisy Items są punktem odniesienia dla mikstur i przedmiotów fabularnych w loot i sklepach.

Sekcje: Skills · Weapons · Enemies · NPC · Locations · Conditions · Items · Consumables (legacy) · Loot tables · Stats / DC / Archetypes

Skills

Skills are abilities characters develop during play, each linked to a core stat. They appear on character sheets and in roll resolution.

Field Type Required Notes
key text ✅ lowercase_snake_case, unique, 1–40 chars
label text ✅ Display name shown to players
linked_stat text ✅ Must be one of: STR, DEX, CON, INT, WIS, CHA, LCK
rank_ceiling number ✅ Max rank achievable (1–10), default 5
description text ❌ Shown in tooltips and roll hints

Example key values are often already loaded from seed data. Re-importing them returns 409 Conflict — use new keys, or in the admin panel enable Skip 409 on bulk import so existing rows are skipped.

Do not include sort_order in import JSON: the server assigns max(existing) + 1 for each new skill (and the next new skill gets the following integer). Optional sort_order in JSON is only if you need an explicit value.

Example JSON 
[
  {
    "key": "athletics",
    "label": "Athletics",
    "linked_stat": "STR",
    "rank_ceiling": 5,
    "description": "Physical effort: climbing, jumping, lifting, sprinting."
  },
  {
    "key": "arcana",
    "label": "Arcana",
    "linked_stat": "INT",
    "rank_ceiling": 5,
    "description": "Knowledge of spells, magical theory, and arcane phenomena."
  }
]

Weapons

Weapons available to characters during combat. Each weapon is linked to a stat for attack rolls and restricted to specific archetypes.

Field Type Required Notes
key text ✅ lowercase_snake_case, unique
label text ✅ Display name
damage_die text ✅ Dice notation: d6, d8, 2d6 etc.
linked_stat text ✅ Stat used for attack rolls (STR/DEX/INT etc.)
allowed_classes array[string] ✅ Subset of: ["warrior", "ranger", "scholar"]
description text ❌ Flavour text; default empty string
weapon_type text ❌ melee | ranged | spell (default melee)
two_handed boolean ❌ Two-handed weapon; default false
finesse boolean ❌ Finesse property; default false
range_m number ❌ Range in metres for ranged weapons; null if not applicable
weight_kg number ❌ Mass in kilograms; default 0
note text ❌ Internal design notes
is_active boolean ❌ Default true

Enemies

Enemy templates used by the GM during combat encounters. Each defines the base stats for that enemy type.

Bulk import accepts canonical fields (hp_base, ac_base, attack_bonus). For convenience, legacy aliases are mapped when the canonical field is omitted: hp → hp_base, ac → ac_base, atk_bonus → attack_bonus.

Field Type Required Notes
key text ✅ lowercase_snake_case, unique
label text ✅ Display name
hp_base number ✅ Base hit points
ac_base number ✅ Base armour class
attack_bonus number ✅ Bonus added to attack rolls
damage_die text ✅ Damage dice (d6, 2d8 etc.)
tier text ❌ weak | standard | elite | boss (default standard)
attacks_per_turn number ❌ Attacks per turn; default 1
damage_bonus number ❌ Flat damage bonus; default 0
damage_type text ❌ physical | magic | fire | poison | misc (default physical)
xp_award number ❌ XP granted on defeat; default 0
conditions_immune array[string] ❌ JSON array of condition keys this enemy ignores; default []
loot_table_key text ❌ Optional reference to a loot table key
drop_chance number ❌ 0.0–1.0 chance the loot table is rolled on defeat; default 1.0
note text ❌ Internal design notes
description text ❌ Flavour text for the GM
is_active boolean ❌ Default true

NPC

NPC catalogue used in Phase 9 for dialogue context, merchants, and location-bound characters. In bulk import for Game Design → NPC, each row maps to npcs plus optional entries in npc_locations.

Field Type Required Notes
key text ✅ lowercase_snake_case, unique (e.g. merchant_aldric)
label text ✅ Display name shown to GM/admin
npc_type text ❌ neutral | merchant | quest_giver | ally (default neutral)
description text ❌ Short flavour/role note
personality_json JSON string or object ❌ Must be valid JSON; API stores it as text. Recommended shape: {"personality":"...","topics":[...],"secret":null}
is_shop boolean / 0|1 ❌ Mark merchant/shop NPC (default false)
shop_inventory_json JSON string or array ❌ Valid JSON. Przykład: [{"type":"weapon","key":"war_axe_light"},{"type":"item","key":"health_potion_small"}] — klucze muszą istnieć w katalogu broni / przedmiotów (game_config_items dla type: item).
is_active boolean / 0|1 ❌ Default true
location_keys array[string] ❌ Optional bindings to game_locations.key. Empty array means global NPC.
Example JSON 
[
  {
    "key": "merchant_aldric",
    "label": "Aldric, kupiec",
    "npc_type": "merchant",
    "description": "Wędrowny kupiec z towarami pierwszej potrzeby.",
    "personality_json": {
      "personality": "sknerski, podejrzliwy, lubi plotki o lokalnych sprawach",
      "topics": ["handel", "ceny", "lokalne wiadomości"],
      "secret": null
    },
    "is_shop": 1,
    "shop_inventory_json": [
      { "type": "weapon", "key": "war_axe_light" },
      { "type": "item", "key": "health_potion_small" },
      { "type": "item", "key": "rope" }
    ],
    "is_active": 1,
    "location_keys": []
  },
  {
    "key": "innkeeper_marta",
    "label": "Marta, karczmarka",
    "npc_type": "neutral",
    "description": "Gospodyni lokalnej karczmy, zna wszystkie plotki.",
    "personality_json": {
      "personality": "gadatliwa, serdeczna, dobra gospodyni",
      "topics": ["plotki", "noclegi", "jedzenie", "lokalni mieszkańcy"],
      "secret": null
    },
    "is_shop": 0,
    "shop_inventory_json": [],
    "is_active": 1,
    "location_keys": ["inn_main"]
  }

Locations

Game locations define the world geography and encounter rules. Macro locations are top-level zones; sub locations are nested under a macro. Each location can have special rules (e.g., no combat in sacred areas) and assigned enemies for random encounters.

Field Type Required Notes
key text ❌ Optional. If omitted, backend auto-generates lowercase_snake_case from label. Must be unique when provided.
label text ✅ Display name shown to players and GM
location_type text ✅ macro (top-level) or sub (nested under macro)
parent_id / parent_key number / text ❌ Required for sub-locations. Prefer parent_key in templates/imports because it is stable and self-contained. Avoid hard-coded parent_id unless you know the DB ID.
description text ❌ Flavour text describing the location
rules object ❌ Supported rules (extensible JSON):
{"no_combat": true, "reason": "Sacred ground"} — combat is forbidden, GM will explain why
{"no_loot": true} — enemies here don't drop loot
{"teleport_blocked": true} — teleportation spells don't work
{"rest_bonus": 2} — resting restores 2x HP
{"mana_regen": 0} — no natural mana regeneration
{"stealth_check": true} — entering requires stealth roll
{"required_item": "torch"} — need specific item to enter
Add custom rules as needed — GM will see them in context.
enemy_keys array[string] ❌ Array of enemy keys that can spawn here. Enemies must exist in the Enemies catalogue.
npc_keys array[string] ❌ Array of NPC keys. Currently placeholder for Phase 9.
is_active boolean ❌ Default true. Inactive locations are hidden from the game.
Example JSON 
[
  {
    "label": "Dark Forest",
    "location_type": "macro",
    "description": "A dense, ominous forest where sunlight barely reaches the ground.",
    "rules": {},
    "enemy_keys": ["goblin", "wolf", "bandit"],
    "npc_keys": [],
    "is_active": true
  },
  {
    "label": "Old Ruins",
    "location_type": "sub",
    "parent_key": "dark_forest",
    "description": "Ancient ruins deep within the Dark Forest.",
    "rules": {"no_combat": false, "loot_bonus": 1.5},
    "enemy_keys": ["skeleton_warrior", "ghost"],
    "npc_keys": [],
    "is_active": true
  },
  {
    "label": "Temple of Light",
    "location_type": "sub",
    "parent_key": "dark_forest",
    "description": "A sacred sanctuary where violence is forbidden.",
    "rules": {"no_combat": true, "reason": "Sacred ground"},
    "enemy_keys": [],
    "npc_keys": [],
    "is_active": true
  }
]
📖 How to Create Custom Rules (click to expand)

The rules field accepts any valid JSON object. You can use predefined rules (shown in the table above) or create your own custom rules that the GM will see in the location context.

Creating Custom Rules in Admin Panel

  1. Go to Game Design → Locations
  2. Expand "➕ Create Custom Rule" section
  3. Fill in the form:
    • Rule Key: lowercase with underscores (e.g., poison_immunity)
    • Label: Display name (e.g., "Poison Immunity")
    • Type: boolean (on/off), number, or text
    • Default: Optional default value
    • Description: What this rule does
  4. Click "Add Rule to System"
  5. New rule appears immediately in the Rules dropdown!

Examples

Rule Key Type Default Description Effect
poison_immunity boolean true Characters in this area are immune to poison Poison conditions won't apply
magic_blocked boolean true Magic doesn't work in this zone Spell attacks fail
healing_bonus number 2 Healing spells restore 2x HP heal_hp × 2
time_limit number 10 Players have 10 turns before collapse Countdown mechanic
required_stat text STR≥15 Need high STR to enter Entry requirement
weather text storm Current weather condition Affects visibility/combat

JSON Examples for Bulk Import

// Simple boolean rule
{
  "key": "cursed_crypt",
  "label": "Cursed Crypt",
  "location_type": "sub",
  "parent_key": "dark_forest",
  "rules": {
    "no_combat": false,
    "magic_blocked": true,
    "healing_bonus": 0.5,
    "reason": "Dark magic suppresses healing"
  }
}

// Complex custom rules
{
  "key": "elemental_forge",
  "label": "Elemental Forge",
  "location_type": "macro",
  "rules": {
    "fire_immunity": true,
    "ice_damage_bonus": 2,
    "required_item": "fire_resistance_ring",
    "max_party_size": 4,
    "respawn_rate": 0.5,
    "weather": "extreme_heat"
  },
  "enemy_keys": ["fire_elemental", "magma_golem"]
}

Tip: Use the "Custom Rules" section in the Add Location form to add one-off rules without adding them to the system.

Conditions

Status effects that can be applied to characters or enemies. Each condition modifies stats for a defined duration.

Field Type Required Notes
key text ✅ lowercase_snake_case, unique
label text ✅ Display name
effect_json text ✅ JSON string with stat_mods and duration
description text ❌ Plain-language explanation shown to players
stackable boolean ❌ Whether multiple instances can stack; default false
auto_remove text ❌ When the engine removes the condition (e.g. end_of_encounter); null = manual only
is_active boolean ❌ Default true

effect_json structure (must be valid JSON encoded as a string): { "stat_mods": { "STR": -2 }, "duration": "3 turns" }

Example JSON 
[
  {
    "key": "poisoned",
    "label": "Poisoned",
    "effect_json": "{\"stat_mods\":{\"STR\":-2},\"duration\":\"3 turns\"}",
    "description": "Toxin weakens muscles. STR -2 for 3 turns.",
    "is_active": true
  },
  {
    "key": "blinded",
    "label": "Blinded",
    "effect_json": "{\"stat_mods\":{\"DEX\":-4},\"duration\":\"2 turns\"}",
    "description": "Cannot see. DEX -4 for 2 turns.",
    "is_active": true
  }
]

Items (game_config_items)

Główny katalog przedmiotów dla gry i dla GM: zbroje, zużywalne (z polami efektu), przedmioty fabularne, klucze fabularne itd. Mikstury i consumables definiuj tutaj jako item_type: consumable z effect_type / effect_dice — to jest preferowane źródło (8H) zamiast osobnej tabeli legacy. Pole effect_json zostaw na rzadkie przypadki (np. stat_mods); dla healów używaj pól efektu.

Field Type Required Notes
key text ✅ lowercase_snake_case, unique, 1–40 znaków
label text ✅ Nazwa wyświetlana
item_type text ✅ weapon | armor | consumable | misc | quest | narrative (domyślnie misc). narrative — przedmioty tylko do kontekstu/opowieści.
description text ❌ Opis dla gracza / GM
value_gp number ❌ Wartość w GP; domyślnie 0
weight_kg number ❌ Masa w kg; domyślnie 0. W imporcie akceptowany jest alias weight (legacy).
allowed_classes array[string] ❌ Podzbiór warrior, ranger, scholar; domyślnie []. Alias: proficiency_classes (stara nazwa w JSON).
ac_bonus number ❌ Dla zbroi / tarcz: bonus do AC; domyślnie 0
effect_type text | null ❌ Dla consumable: heal_hp | restore_mana | remove_condition | add_condition | stat_buff | misc. Jeśli consumable i brak — backend ustawi misc.
effect_dice text | null ❌ np. 2d4 — tylko wzorzec kości (^\d*d\d+$); stały dodatek w effect_bonus
effect_bonus number ❌ Płaski dodatek do efektu; domyślnie 0
effect_target text ❌ self | ally | any (domyślnie self)
charges number ❌ Liczba użyć na stos; minimum 1
approved number (0|1) ❌ Zatwierdzenie treści; domyślnie 1
ai_generated number (0|1) ❌ Oznaczenie pochodzenia; domyślnie 0
effect_json text ❌ Opcjonalny JSON string — używaj oszczędnie; efekty heal preferuj przez effect_*
note text ❌ Notatki projektowe
is_active boolean ❌ Domyślnie true

Consumables — game_config_consumables (legacy)

Osobna tabela historyczna; nadal można importować dla kompatybilności i odwołań consumable_key w loot. Preferowany model (8H): wpisy item_type: consumable w game_config_items — tam ustala się efekty i klucze używane jako item_key w loot / sklepach. Nie duplikuj mikstur w obu miejscach bez potrzeby.

Field Type Required Notes
key text ✅ lowercase_snake_case, unique
label text ✅ Display name
description text ❌ Flavour text; default empty string
effect_type text ❌ heal_hp | restore_mana | remove_condition | add_condition | stat_buff | misc (default misc)
effect_dice text ❌ Dice expression e.g. 2d4; null uses flat effect_bonus only
effect_bonus number ❌ Flat bonus; default 0
effect_target text ❌ self | ally | any (default self)
weight_kg number ❌ Mass in kilograms; default 0
charges number ❌ Uses per inventory stack; default 1
value_gp number ❌ Cena / wartość w GP (API 8H; w JSON bulk import: value_gp). Alias w starych plikach: base_price — silnik mapuje na to samo pole.
note text ❌ Internal design notes
is_active boolean ❌ Default true

Loot tables

Ważone tabele dropów: jeden obiekt na tabelę. Opcjonalnie entries — każdy wiersz ma dokładnie jedno z: item_key | weapon_key | consumable_key. Mikstury z katalogu game_config_items podawaj jako item_key (np. health_potion_small); consumable_key zostaw dla wpisów wyłącznie w game_config_consumables (backend może mapować consumable_key → item_key przy imporcie).

Field Type Required Notes
key text ✅ lowercase_snake_case, unique per table
label text ✅ Display name
description text ❌ Default empty string
is_active boolean ❌ Default true
entries array ❌ Loot rows; omit or [] for an empty table
entries[].item_key / weapon_key / consumable_key text ✅ per entry Exactly one must be set; must match an existing row
entries[].weight number ❌ Relative weight; default 10; must be ≥ 1
entries[].qty_min / qty_max number ❌ Defaults 1; must be ≥ 1 and qty_min ≤ qty_max

409 on table key: with Skip 409 enabled in the admin panel, the create-table step is skipped for duplicate keys, but entries are still POSTed (upsert) to the existing table.

Example JSON 
[
  {
    "key": "example_loot_table",
    "label": "Przykładowe dropsy",
    "description": "Klucze muszą istnieć w odpowiednich katalogach.",
    "is_active": true,
    "entries": [
      { "item_key": "rope", "weight": 10, "qty_min": 1, "qty_max": 2 },
      { "item_key": "health_potion_small", "weight": 25, "qty_min": 1, "qty_max": 1 },
      { "weapon_key": "war_axe_light", "weight": 5, "qty_min": 1, "qty_max": 1 }
    ]
  }
]
