## Clarification questions before doc update / implementation

Things I genuinely can't decide without you:

### 1. Equipment slot model (T20 + T35)
Spec says 6 anatomical slots (Head / Torso / L Hand / R Hand / Feet / Hands). Code has 3 functional slots (main_hand / off_hand / armor). Functional model is simpler and matches what's actually equipable. Six-slot model would need new item types (helmets, boots, gloves).
- **Question:** Stay with 3 slots and update spec? Or expand to 6 and add new equipment types?

### 2. Condition naming consistency (T16)
Code uses `fear_shaken`, `terror`, `break`. Spec uses `FRIGHTENED`, `PANICKED`, `BREAK`. Mechanically equivalent.
- **Question:** Rename code to match spec, or update spec to match code?

### 3. T34 enemy HP visibility
Spec says enemies show only a bar (no exact numbers). Implementation shows `current/max`. Functional info parity with player.
- **Question:** Hide enemy HP numbers (more atmospheric, matches spec)? Or keep numbers (more readable for combat math)?

### 4. T42 Persistent Hero scope
Schema is half done but endpoints/UI missing. The spec describes a between-campaigns REST state with XP spending, hero journal, history view. This overlaps with **T45 Hero Journal** in Phase 10.
- **Question:** Treat T42 as "schema-only / deferred" until T45? Or implement the missing endpoints now?

### 5. T44 Debug System scope
Admin-only backend exists; spec'd player-facing debug panel + `/debug` slash commands missing.
- **Question:** Implement player-facing debug per spec? Or close T44 as "admin-only, no player exposure needed"?

### 6. T39 Auth model
Spec says JWT; reality is session/cookie or bearer (no JWT found). Spec also requires brute-force lockout and onboarding overlay.
- **Question:** Migrate to JWT? Or update spec to reflect actual model? Lockout and onboarding genuinely missing — implement?

### 7. XP loop priority (T25V2 + T26 + T35 + T45)
The XP earning side works; spending side completely lacks player UI. Long rest endpoint missing.
- **Question:** Is restoring the XP loop the next priority? If so, what's the minimum viable: progress bar + level display + skill/stat spending UI + `/rest` endpoint?

### 8. Smart Entry Q&A mode (T33SA)
Form-first JSON-fill shipped. Spec also wanted a Q&A visual-questionnaire flow with option cards.
- **Question:** Q&A mode still wanted, or is form-first sufficient and we update the spec?

### 9. T16 Fear naming `fear_shaken` and friends
Closely related to question 2 but worth separate decision because of DB migration cost. Renaming the DB enum values would require a data migration + admin UI sync.
- **Question:** Worth the migration, or accept the divergence?

### 10. Spec docs accuracy
Some specs (T39 JWT, T20 6-slot, T34 enemy-HP-bar-only) describe features that were never implemented and likely never will be in current form.
- **Question:** Do we treat the specs as "intent at time of writing" (read-only history) and update them to match reality? Or treat reality as the gap and chase the spec?
